配置 schema v2 栏目级目录声明 + 显式覆盖 + 排序

schema_version: 2
site_title: WaveformAnalysis 文档中心

sections:
  - id: user-guide
    title: 用户指南
    source_dir: docs/user-guide   # 新增:目录自动发现
    index_route: user-guide/index.html
    nav_weight: 10               # 新增:栏目排序

  - id: features
    title: 功能特性
    source_dir: docs/features
    index_route: features/index.html
    nav_weight: 20

  - id: plugins
    title: 插件系统
    source_dir: docs/plugins
    index_route: plugins/index.html
    nav_weight: 30
    exclude:                    # 新增:排除自动生成目录
      - reference/**
      - **/README.md           # README 用作栏目索引,不进页面列表
    pages:                      # 显式覆盖(优先级高于自动发现)
      - source: docs/plugins/PLUGIN_SYSTEM_OVERVIEW.md
        route: plugins/overview.html
        title: 插件系统与模板 API
    page_providers:
      - plugin_reference       # 插件页保留在插件栏目

  - id: api-reference       # docstring/反射生成页纳入导航
    title: API 参考
    nav_weight: 40
    page_providers:            # 新增:注册代码生成页;路由由生成器属主提供
      - context_reference
      - accessor_reference

  - id: cli  … nav_weight: 50
  - id: architecture … nav_weight: 60
  - id: development … nav_weight: 70
  - id: visualization … nav_weight: 80
迁移策略:一次性将 docs/site-guides.yaml 更新为 schema_version: 2, 由测试与 site-web 生成验证。避免长期保留 v1/v2 分支，使维护入口真正收敛。

frontmatter 规范 每篇文档的控制放在文件头,而非堆在配置里

---
title: 缓存架构说明      # 覆盖 H1,决定侧边栏标题
summary: 缓存分层、键生成与失效规则
nav_weight: 10            # 同栏目内排序(缺省按文件名序)
exclude_from_nav: false  # true = 进站但不出现在侧边栏
hidden: false             # true = 完全不收录
---
字段用途缺省
title覆盖 H1,用于侧边栏/面包屑H1 文本
summary覆盖首段,用于栏目索引/搜索正文首段
nav_weight同栏目内排序文件名排序
exclude_from_nav进站但不在侧边栏(仍可被链接)false
hidden完全不收录false
mistune 3.3 无内置 frontmatter 插件 → 在 site_guides.py 内自写一个约 15 行解析函数,可控、可单测。

docstring 与 markdown 的配合模型 三层分工,导航统一,各司其职

层事实源在网站中呈现为内容职责
API / 契约 代码 + docstring(签名、参数、返回、插件 provides/config/dtype) API 参考页 —— 罗列方法与签名,如 context.html、accessors、插件页 「是什么 / 长什么样」—— 自动提取,新增公开方法自动同步(现有 Context 反射机制)
指南 markdown(docs/*.md) 教程 / 指南页 —— 讲「怎么用、为什么」 「怎么用 / 为什么」—— 解释与场景
导航 site-guides.yaml 侧边栏菜单 / 首页 / 栏目索引 —— 决定页面组织与顺序 「谁进站、放哪个栏目、什么顺序」—— page_providers 选择生成页类别;provider 返回实际节点和路由
配合规则(防重复 / 防冲突):
① 事实性内容只写一处 —— 签名 / 参数只在 docstring,解释只在 markdown,不双写;
② 指南页引用参考页用链接锚点(如 context.html#get_data),不复制 API 细节;
③ 生成器里硬编码的叙述块(intro_blocks / _CONTEXT_DESCRIPTIONS)作为过渡兜底,后续逐步迁到 markdown / docstring(写入里程碑)。

一一对应:源文件 → 生成器 → 输出页面 具体到文件路径

页面源文件(具体位置)生成器输出 HTML导航现状
Context 参考页 waveform_analysis/core/context.py(class Context,方法 docstring + 反射签名) site_doc_generator._build_context_documentation_page docs/_site/contexts/context.html 侧边栏「Context 与适配器」硬编码
Accessor 参考页 utils/peak_channel_accessor.py、utils/s1_s2_pair_accessor.py、core/data/records_view.py build_accessor_views docs/_site/accessors/peak-channel-accessor.html 等 侧边栏「Accessor 接口」硬编码
插件参考页 core/plugins/builtin/*/plugin.py(provides / config / dtype 声明) plugin_doc_generator docs/_site/plugins/*.html、index.html、lineage.html 侧边栏「插件系统」硬编码
架构指南页 docs/architecture/ARCHITECTURE.md site_guides(读 yaml) docs/_site/architecture/system.html yaml architecture 栏目
插件指南页 docs/plugins/PLUGIN_SYSTEM_OVERVIEW.md site_guides(读 yaml) docs/_site/plugins/overview.html yaml plugin-system 栏目
这就是「不统一」的具体表现:前三行(docstring 生成的参考页)不走 yaml,是生成器 + 模板硬编码进导航;只有后两行(markdown 指南页)由 site-guides.yaml 管理。 统一后,前三行由 page_providers 注册到栏目;每个 provider 继续拥有其实际页面、路由和生成时机, 与后两行在同一棵侧边栏按 nav_weight 排序。

文档多了会不会冲突 冲突在生成期报错,绝不静默覆盖

冲突类型防护机制
路由撞车(两个 md 生成同一 URL) 路由 = 「栏目 id + 文件 stem」确定性生成;生成器检测重复路由 → 直接报错(现有 load_guide_manifest 已检查 duplicate route)
与插件 / 参考页撞(自动扫描到 plugins/ 目录,和插件生成站冲突) 生成器统一校验 guide route 与生成页路由冲突(_publish_guides 已有)→ 报错,用 exclude 排除自动生成目录
链接失效(A 篇链到 B 篇,B 被 exclude / hidden) 生成时对「未收录链接」报 warning(现有 resolve_url);死链校验兜底
同页锚点重复 生成器自动加序号后缀(现有 slug 去重)
导航标题重复(两篇 title 一样,侧边栏混淆) CI 增加「导航重复标题」检查(新增)
误收(草稿 / 内部笔记被自动收进站) 栏目级 exclude:(glob)+ 单篇 hidden: true;可用 _ 前缀文件名约定「不进站」
关键原则:冲突一律在生成时报错、CI 失败,绝不让两篇文档静默互相覆盖。同名文件靠「栏目前缀」天然隔离(不同栏目目录互不撞);每步生成后 git diff + 死链校验,出问题马上定位到具体文件。

改完后的目录 推荐方案：栏目配置 + 目录发现；生成产物不入库

docs/
├── site-guides.yaml                 # v2：栏目、顺序、扫描边界、生成页 provider
├── README.md                        # GitHub/源码浏览入口；保留精简链接，不重复站点导航
├── user-guide/                     # 人类文档栏目；Markdown 由目录发现收录
├── features/
├── plugins/
│   ├── PLUGIN_SYSTEM_OVERVIEW.md
│   ├── guides/
│   └── reference/                  # 插件参考由 generator provider 生成，不被 Markdown 扫描
├── api/  cli/  architecture/  development/
├── analysis/  optimization/  visualization/
├── agents/                         # LLM 协作体系，保持独立，不进入人类站点扫描
└── _site/                          # site-web 原子发布的派生产物；gitignore，不手工编辑

waveform_analysis/utils/
├── site_guides.py                  # 解析 schema、frontmatter、目录发现、导航序列
├── site_doc_generator.py           # 汇集 Markdown 与代码生成页，发布统一站点
└── templates/web/                  # 侧边栏、栏目索引、上一页/下一页、源文件入口

tests/
├── test_site_guides.py             # schema、发现、排序、frontmatter、冲突
└── test_cli_docs_site_publish.py   # 原子发布与本地链接校验
关键边界:目录是内容归属，site-guides.yaml 是栏目和发布策略， frontmatter 是单页元数据。代码生成的 Context、Accessor、Plugin 参考页不复制成 Markdown， 而是由 provider 返回导航节点接入同一棵树。docs/_site 只从这些源生成。
README 说明:本次保留 README 为 GitHub/源码浏览入口，不由站点生成。是否迁移或删除 README 要先盘点现有链接，并作为独立后续任务决策；不阻塞导航统一。

范围与「不改的东西」 明确边界,避免过度改造

纳入统一(面向人类的文档)

  • user-guide / features / plugins
  • api / cli / architecture
  • development / visualization / analysis / optimization
  • 各栏目 README 保留为源码浏览入口，不承担站点导航真源
  • CI 增加配置/provider 合法性 + 站点链接 + 生成产物边界校验

保持不变

  • 自研生成器 site_doc_generator.py 不替换
  • 插件谱系图(React lineage)、搜索、深浅主题
  • docs/agents + AGENTS.md(面向 LLM,独立)
  • 插件自动 INDEX.md 生成机制
  • 不引入 MkDocs / Sphinx 新依赖

README 后续收敛 独立决策;不纳入导航统一的首个交付

首个交付的决策:保留 docs/README.md 与各栏目 README 作为 GitHub/源码浏览入口， 不自动生成、不删除、不改变既有链接。待导航统一稳定后，再单独决定哪些 README 应保留、精简或迁移。
类别对象处理
