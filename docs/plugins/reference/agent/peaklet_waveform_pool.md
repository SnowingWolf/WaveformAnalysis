## Config

- 无可配置项

## Behavior Notes

- Waveform construction options are owned by `peaklet_waveforms`; `peaklet_waveform_pool` has no independent configuration.
- Custom `peaklet_waveforms` providers must implement `build_pair(context, run_id)` so a missing pool can be rebuilt after a waveform cache hit.

## Execution Path

`peaklet_waveform_pool` 依赖链入口：
`peaklet_waveforms -> peaklet_waveform_pool`

## Failure Modes

- A custom `peaklet_waveforms` provider does not implement `build_pair(context, run_id)`.
- Legacy configuration remains under `peaklet_waveform_pool.*` instead of the canonical `peaklet_waveforms.*` namespace.

## Change Playbook

1. v2.0.0: `peaklet_waveform_pool` now depends on `peaklet_waveforms`, so waveform version, config, dtype, and upstream lineage invalidate the paired pool cache.
2. v2.0.0: Move all former `peaklet_waveform_pool.*` settings to `peaklet_waveforms.*`; the old namespace is ignored with a migration warning.
3. Keep `peaklet_waveforms` index offsets and `peaklet_waveform_pool` values generated by the same `build_pair` implementation.
