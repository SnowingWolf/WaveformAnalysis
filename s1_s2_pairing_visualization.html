S1-S2 配对逻辑说明

液氙暗物质探测器中的信号关联算法

物理背景

在液氙时间投影室（TPC）中，粒子散射会产生一对信号：

  • S1（初级闪烁光）：粒子直接激发液氙原子产生的瞬时光信号
  • S2（次级闪烁光）：电离电子漂移到探测器顶部后产生的延迟光信号

配对目标：将同一次散射事件产生的 S1 和 S2 关联起来，重建完整的物理事件。

两层架构设计

peaks + peaklet_s1_s2 分类结果 ↓ ┌──────────────────────────────────────────┐ │ Phase 1: 候选生成 │ │ S1S2PairCandidatesPlugin │ │ • 生成所有物理允许的配对候选 │ │ • S2-anchor + 二分搜索 │ │ • O(M log N) 时间复杂度 │ │ • 只做硬约束，不判断好坏 │ └──────────────────────────────────────────┘ ↓ s1_s2_pair_candidates (所有候选对, selected=False) ↓ ┌──────────────────────────────────────────┐ │ Phase 2: 配对选择 │ │ S1S2PairSelectionPlugin │ │ • 对候选打分 │ │ • 选择最佳配对 │ │ • 计算歧义指标 │ │ • 设置 selected=True │ └──────────────────────────────────────────┘ ↓ s1_s2_pairs (最终配对结果)

Phase 1: 候选生成

核心算法：S2-anchor + 二分搜索

以每个 S2 为基准，向前搜索时间窗口内的 S1 候选

for s2 in s2_peaks_sorted: s2_time = s2["center_time"] # 物理约束：漂移时间窗口 s1_time_min = s2_time - max_drift_time # 例如 50 μs s1_time_max = s2_time - min_drift_time # 例如 0 ns # O(log N) 二分查找 left = np.searchsorted(s1_times, s1_time_min) right = np.searchsorted(s1_times, s1_time_max) # 只遍历候选范围 for s1 in s1_peaks_sorted[left:right]: create_candidate(s1, s2) # 创建候选对

硬约束条件

  • 时间因果性：t_S2 > t_S1（S2 必须在 S1 之后）
  • 漂移时间窗口：min_drift < (t_S2 - t_S1) < max_drift
  • 可选面积阈值：过滤掉太小的信号

输出内容

类别 字段 说明
标识 pair_id, s1_peak_id, s2_peak_id 候选对的唯一标识
时间 s1_time, s2_time, drift_time 时间戳和漂移时间（ps 精度）
观测量 s1_area, s2_area, log10_s2_s1 信号面积、能量比等
歧义统计 n_s1_candidates_for_s2 该 S2 有多少个 S1 候选
标志位 flags FLAG_MULTI_S1_CANDIDATE 等

Phase 2: 配对选择

目标：为每个 S2 选择最优的 S1

当前实现 v0.1 使用 largest 模式：选择面积最大的 S1

# largest 模式：选择面积最大的 S1 for s2 in unique_s2s: # 找到该 S2 的所有 S1 候选 s2_candidates = candidates[candidates["s2_peak_id"] == s2] # 计算分数：score = log(1 + S1_area) scores = np.log1p(s2_candidates["s1_area"]) # 选择分数最高的候选 best = s2_candidates[scores.argmax()] best["selected"] = True # 计算与次优候选的分数差（量化可靠性） if len(scores) > 1: delta = scores[0] - scores[1] best["delta_score_to_next_best"] = delta

选择策略

模式 状态 说明
largest ✅ 已实现 选择面积最大的 S1（假设更大的 S1 更可靠）
nearest 🔄 预留 选择漂移时间最短的 S1（时间最近）
best_score 🔄 预留 综合打分（时间 + 面积 + 通道数 + S2/S1 比值）
all 🔄 预留 不做选择，保留所有候选供后续分析

多个 S2 距离很近的情况

场景：两个 S2 间隔仅 2 μs

时间轴 → max_drift = 50 μs ←─────────────→ S1_A ─┐ ┌───────────────┐ t=0 │ │ 搜索窗口 │ │ │ for S2_X │ S1_B ─┤ └───────────────┘ t=5μs│ │ │ │ │ S2_X (t=50μs) │ │ ├───────────────┤ drift=45μs │ ┌──┴──────────┐ │ │ 搜索窗口 │ │ │ for S2_Y │ └────────────┴─────────────┘ │ S2_Y (t=52μs) ← 距离仅 2μs

当前实现的行为

独立处理每个 S2，不考虑全局最优：

# S2_X 的配对（独立搜索） for S2_X: 搜索 [0, 50μs] 范围内的 S1 → 找到 S1_A (drift=50μs) → 找到 S1_B (drift=45μs) → 创建 2 个候选对 # S2_Y 的配对（独立搜索） for S2_Y: 搜索 [2μs, 52μs] 范围内的 S1 → 找到 S1_A (drift=52μs) → 找到 S1_B (drift=47μs) → 创建 2 个候选对 # 结果：4 个候选对 • S1_A 有 2 个 S2 候选 → FLAG_MULTI_S2_CANDIDATE • S1_B 有 2 个 S2 候选 → FLAG_MULTI_S2_CANDIDATE • S2_X 有 2 个 S1 候选 → FLAG_MULTI_S1_CANDIDATE • S2_Y 有 2 个 S1 候选 → FLAG_MULTI_S1_CANDIDATE

Phase 2 选择结果

以 largest 模式为例：

# 为 S2_X 选择 candidates: (S1_A, S2_X), (S1_B, S2_X) 选择: S1_B (面积更大) → selected=True # 为 S2_Y 选择 candidates: (S1_A, S2_Y), (S1_B, S2_Y) 选择: S1_B (面积更大) → selected=True # 潜在冲突：S1_B 被两个 S2 同时选中！
⚠️ 当前实现的局限性
  • 贪心策略：每个 S2 独立选择最优 S1
  • 不保证全局最优：可能同一个 S1 被多个 S2 选中
  • 不处理竞争：没有冲突解决机制

物理解释

多个 S2 距离很近可能代表：

1. 多重散射（Multiple scatters）

一个粒子在探测器内发生多次散射

  • 应该有：1 个 S1，多个 S2
  • 理想配对：S1_B → (S2_X, S2_Y)

2. Pile-up 事件

两个独立粒子几乎同时进入探测器

  • 应该有：2 个 S1，2 个 S2
  • 理想配对：S1_A → S2_X, S1_B → S2_Y

3. Single electron + 真实事件

S2_Y 可能是单电子信号（没有对应的 S1）

  • 应该有：1 个真实 S1，1 个真实 S2，1 个单电子 S2
  • 理想配对：S1_B → S2_X，S2_Y → 孤立

如何识别和处理

诊断代码

# 获取最终配对 final_pairs = pairs[pairs["selected"]] # 找出被多次选中的 S1 s1_usage = {} for pair in final_pairs: s1_id = pair["s1_peak_id"] s1_usage[s1_id] = s1_usage.get(s1_id, 0) + 1 duplicates = {s1: count for s1, count in s1_usage.items() if count > 1} print(f"被多次选中的 S1: {duplicates}") # 检查 FLAG_MULTI_S2_CANDIDATE ambiguous = final_pairs[final_pairs["flags"] & FLAG_MULTI_S2_CANDIDATE] print(f"有多个 S2 候选的配对: {len(ambiguous)}") # 检查竞争激烈程度 close = final_pairs[final_pairs["delta_score_to_next_best"] < 0.1] print(f"竞争激烈的配对: {len(close)}")

策略 适用场景
事后人工检查 标记 FLAG_MULTI_S2_CANDIDATE 或 FLAG_CLOSE_COMPETITOR 的配对需要额外验证

总结

  • 当前实现采用 贪心策略，每个 S2 独立选择最优 S1
  • 多个近距离 S2 会产生 候选重叠，可能导致同一个 S1 被多次选中
  • 通过 FLAG_MULTI_S2_CANDIDATE 和 delta_score_to_next_best 可以识别歧义情况
  • 需要更高级的算法（如全局匹配）来真正解决多重散射和 pile-up 问题
  • 当前系统适合 单散射事件，复杂场景需要事后人工检查或算法升级
